# DSH-PackFabric

这里放着 DSH-Melody-Launcher 的整合包理念，以及官方默认整合包的内容基线。

## 一个整合包是怎么成立的

DSH 分成两半。

一半是 DSH 本体，npm 上那个 `@deepseek-ai/dsh` 运行时。它装在机器级共享的目录里，同版本的包共用同一份，本体不进包。

另一半是包自己的一套东西：Agent 预设、技能、插件、配置和外观。你的包打开是什么样子、能干什么，全由这部分决定。

两半之间靠一个挂钩连着。导入别人的包时，只要挂钩对得上，接上就能用。

挂钩在包里对应三个具体的位置：

| 挂钩 | 位置 | 作用 |
| --- | --- | --- |
| 版本引用 | `profiles/<id>/profile.yaml` 里的 `dshVersion` | 说明这个包要接哪个 DSH 本体 |
| 启用清单 | `profiles/<id>/package.json` 的 `dsh.profile.bundles` | 说明包里哪些插件预设是开着的 |
| 家目录指针 | 启动时注入子进程的 `DSH_HOME` | 把本体的读写落到这个包的家目录上 |

启动器做的事很朴素：拿 `dshVersion` 找到本机那个本体，把 `DSH_HOME` 指到包的家目录，然后启动。右边那套东西是 DSH 自己从家目录读出来的，启动器不参与解释。

## 导出打包：整个家目录，不留清单

整合包走快照形式。所谓快照，就是把包的家目录原样压进 zip：插件本体、`node_modules`、技能、预设、配置、外观、随包的二进制，全都进去。导入则是解压成一个新的隔离家目录，解开就能启动，不联网重装依赖。

不做"清单加联网重装"那一套，理由很实际。这个启动器是给完全不懂技术的人用的，通过 B 站链接发出去，而 GitHub 和 npm 在有些线路上就是连不上、或者只有几十 KB/s。一个还需要联网装配的整合包，对这些用户来说不叫整合包。所以体积的代价是认下来的：官方包 100MB 以上，下载还得配自动换源兜底。

导出时默认剔除个人数据。API 凭据、会话记录、附件、用量、任务板、日志和匿名标识都不出去。绝对路径会相对化，机器相关的字段（`profile.yaml` 的 `source.path`、`.npmrc` 里的 token、`settings.yaml` 里的密钥）会被清洗掉。想连会话记录一起备份，要在导出对话框里显式勾选；勾出来的包文件名带「·含隐私」后缀，而且它不是可以拿去分享的包。

## 唯一的联网步骤

快照导入有一个正当的联网场景：本机没有包引用的那个 DSH 版本。本体是机器级共享的、故意不进包，缺了就得补，大约 100MB。除这一处以外，导入导出过程中任何触网的行为都算 bug。

补装本体的下载也是镜像优先，npmmirror 和华为云排在前面，官方源兜底。校验类的请求顺序反过来，权威源在前。让镜像自己校验自己的载荷，等于没校验。

## 两个坑

这两条都不是启动器能修好的，它们是 DSH 存储层本身的性质。写在这里是免得有人重复踩。

会话记录按绝对工作目录归堆。包导出到另一台机器，那台机器上没有同样路径的项目目录，那些会话就不显示。档没坏，只是看不见。所以跨机器搬包，搬得走插件、技能和预设，搬不走对话历史，除非两边项目路径一模一样。

DSH 的会话格式只往上迁移，没有降级边。新版写过同一个家目录之后，旧版本拒绝打开里面的日志。轻的症状是记录看不见，重的话 DSH 会在绑定端口之前就退出。因此"升到新版、再把旧版包拿回来跑"这条路在代码里是拦掉的。

## 官方包基线

`baseline/` 是官方默认整合包的受控内容，在 launcher 仓库里同样受版本控制，构建过程不依赖维护者本机状态。

```
baseline/
  manifest.json          组装规则：装哪些包、带哪些技能、版本号怎么编
  pnpm-workspace.yaml    nodeLinker: hoisted，node_modules 平铺，解开即用
  settings.yaml          包内 DSH 配置
  skin-center-active.json { active: null }，导入后外观钉回 DSH 原生无皮肤
  skills/                随包的技能文本
```

官方包版本号 = 适配的 DSH 版本 + 序号。`0.1.5-rc.2.1` 挂的是 DSH `0.1.5-rc.2`，看版本号就知道该配哪个本体。

内容基线是 web-all 全家桶，加上 officecli 技能四件（含包自带的 `tools/officecli/officecli.exe`）、humanizer-zh 和 find-skills，外观用 DSH 原生。

## 不在这套体系里的东西

有两样东西看着相关，其实分开管。

应用加载项是机器级全局资源，有自己的独立运行目录。整合包只记录"我依赖哪些应用、要不要随包启停"，本体跨包共享，道理和 DSH 版本一样。

任务工作区里的临时依赖是另一回事，比如 agent 为了做视频在工作区 `npm install remotion`。它装在工作区、跟着任务存亡，启动器的市场与整合包体系不管它，它也不进导出包。
